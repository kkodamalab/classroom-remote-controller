## 2026-10-22 JST：操作失敗の診断対応

実機報告ではiPhone Safari→Portable EXEのWebRTC接続・PC承認・操作要求到達は成功し、PowerPoint/Chromeの全操作が拒否されました。実機の根本原因は未確定です。共通ガード、HWND/PID/EXE比較、ワーカースレッド、COM初期化・文書/スライドショー識別を調査しました。ワーカーのCOM初期化は既存コードにもあり、未初期化が原因だとする証拠はありません。

確定した別の不具合は、対象一覧の更新で選択が消えることです。Qt offscreenテストで同じHWND/PID/EXEのタイトル変更・一覧更新は選択維持、HWND変更は未選択になることを検証しました。報告された全失敗の原因だとは断定しません。

- Python：既存26件を維持し、計58件成功（Linux Python 3.12）。Chrome相当のスクロール・PageUp/Down・履歴移動、フォーカス不一致と復帰、HWND/PID/EXE変更、プロファイル不一致、PowerPoint通常表示/スライドショーの前後、他文書拒否、COM失敗、承認失効、UIスレッドでの対象確定とワーカーでのCOM初期化/解放、ログ・スマホへのコード反映と秘密情報除外、Qtの承認ボタンを検証。
- Web：TypeScript/Viteビルド成功。`tests/browser_diagnostics.cjs` はPeerJSを明示的にモックしたブラウザ契約テスト。QRフラグメント消去、承認前無効化、6種類の日本語エラー、内部文字列の非表示、操作拒否後も再接続不要、前面状態での無効化/復帰、説明、3タブ・モバイル幅、緊急切断、デモを対象とします。
- Windowsの本物のChrome/PowerPoint操作、iPhone Safari実機での今回修正の成功：未検証。モックの成功を実機成功として扱いません。
- 実WebRTC/QR接続の過去の検証は以下に記載。今回は外部PeerJS/STUN/TURN相互運用テストを再実行していません。

PCログは操作番号、プロファイル/アクション、選択・前面のHWND/PID/EXE、固定、判定結果、例外分類、ネイティブエラー番号を表示します。予期しない例外はパス・ソース行・例外メッセージ・ローカル変数を除いたスタックを表示します。スマホには許可済みコードと日本語説明のみを送り、ローカル診断情報は送りません。
